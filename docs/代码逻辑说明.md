# MD 卡图 Mod 工具 — 代码逻辑说明

> 软件功能与使用方法见《功能说明文档.md》，本文档面向代码阅读与二次开发。

## 1. 技术栈与模块划分

| 项 | 说明 |
|---|---|
| 界面 | Tkinter（ttk） |
| 核心依赖 | UnityPy（解析/重打包 Unity AssetBundle）、Pillow（图像处理） |
| 打包 | PyInstaller 单文件 exe（`MD卡图Mod工具.spec`，以 `SPECPATH` 为基准定位 `app.py`，可在任意工作目录调用；显式 collect_all 收集 UnityPy、texture2ddecoder、fmod_toolkit、pyfmodex、astc_encoder、archspec——缺了会导致卡图预览/读取失败） |

```
app.py（界面层）
 ├── core.py（路径/配置/备份/manifest/还原/进程检测/Mod包扫描）
 ├── cards.py（卡图索引 SQLite/查询/卡名加载/卡图读写/镜像同步）
 │    └── 依赖 core 的 Paths、Manifest、write_bundle_bytes
 ├── overframe.py（超框卡图合成、of_card_asset 登记表读写、写入/还原）
 │    └── 依赖 core 的 RESOURCE_DIR、write_bundle_bytes、restore_one
 ├── overframe_ui.py（超框制作对话框，按需 import）
 └── gamedata.py（data.unity3d 解密 → 官方卡名，仅索引重建时调用）
```

### 超框卡图（overframe.py / overframe_ui.py）

- 素材：`core.RESOURCE_DIR / tools`（打包后在 `_MEIPASS`）。`border/*.png`=边框叠加图（下拉栏列出全部，`border_options()` 扫描目录生成）；卡框不随包，只用游戏 `data.unity3d` 或本地图片
- `render(paths, card_id, art, subject, scale, dx, dy, lore_alpha, border, frame, layout, frame_source, frame_file, over_layer, blank_color, fast)` → 704×1024，图层顺序与游戏一致：卡框 → 背景填插图窗 → 边框叠加 → 主体 → 连接箭头点亮 → 效果框按透明度压顶 → 超框层（整卡叠加，alpha 作遮罩）；`art` 为空时 `base_art()` 读游戏当前插图（已是超框则摊回 704 再裁插图窗）；`frame_source`：game=游戏 `data.unity3d` 的 `card_frameNN`、file=本地 PNG；`border`：`tools/border` 下的文件名，空字符串=不变边框；`layout` 决定插图窗/效果框版式，固定按原卡图：普通卡 `LAYOUT_NORMAL=1`、灵摆卡 `LAYOUT_PENDULUM=13`（优先用编辑记录里保存的 `layout`；没有记录时按索引原图尺寸判定，判定时排除 `over=1` 的超框行，避免 512×1024/704×1024 的超框贴图被当成灵摆，不随所选型号变化）
- 素材来源：`game_frame_ids()/game_frame_image()` 直接解包游戏数据（按 Bundle 大小+时间缓存扫描结果，图片内存缓存）；超框层只接受本地图片，不再从游戏内超框贴图导出
- 界面上不再提供跨框方式选项，统一按插图窗铺满后放大 1.38×（只跨出框线），缩放上限 180%；旧的整卡跨框分支已删除
- 插图层可留空（`art="__blank__"`），此时用 `blank_color` 给插图窗铺一层不透明底色，避免写入透明窗口后游戏底层透出
- 卡图工程：`export_project()` 把该卡参数 + 用到的素材打包成 zip（`params.json` + `art/subject/frame/over`，`border` 只记 `tools/border` 下的文件名），`import_project()` 解到 `core.TOOL_DIR/overframe/imported/<卡号>/` 并返回可直接回填界面的参数
- `remove()`（窗口内「还原这张卡」）：按记录的 `ids` + `art_rels` 恢复该卡及同名同图卡的全部 Bundle，再撤销这些卡号的超框登记并删除编辑记录；若是最后一张超框且登记表有备份，整表还原
- `render` 中没选主体时，`scale/dx/dy` 作用于背景卡图（窗口内裁剪）；`subject_image()` 对无 alpha 的 JPG 按四边中位色漫填去底，并裁掉透明留白
- `apply()`：`_illust_rels()` 用 `CRC32("Card/Images/Illust/{kind}/{cid}")` 定位 tcg/ocg/common × local/stream 的全部 Bundle，逐个 `_replace_illust()`（`set_image` 写 704×1024，BC7 失败回退 RGBA32）→ `core.write_bundle_bytes()` 备份并写回 → `_register()` 追加 `(cid, cid)`
- `_register()`：`gate_bundle_path()` 定位 `0000/99/99f84cce`（固定 ID 找不到时扫描 `0000` 下 ≤40000 字节文件探测 `of_card_asset`；只要求含该表，不要求包含 data.unity3d 内置表的全部条目）→ 若该卡已有登记（官方超框，映射到别的底图）则**不动登记表**，只换纹理；否则在本机现有登记表上追加一条 `(cid, cid)` → `_gate_bytes_with()` 以 `<HH>` 重写 TextAsset → lz4 重打包写回；`_replace_illust()` 写入 Bundle 内全部 Texture2D（同卡多份/多格式一起换）
- `forget(paths, manifest, card_id)`：还原管理页/全部还原时撤销超框登记并清理编辑记录，最后一个超框撤销时整表还原
- `edits.json`：`{card_id: {art, subject, scale, dx, dy, lore_alpha, border, frame, frame_source, frame_file, art_rel, art_rels, ids, blank_color}}`，素材副本在 `overframe/edits/`；`border` 只存 `tools/border` 下的文件名，旧记录的 `border_file`/`prismatic` 加载时按文件名映射或回退为「不变边框」
- UI：`OverframeDialog(app, card_id, card_name)` 通过 `app.run_bg()` 后台执行合成/写入，完成回调刷新状态与预览


### 路径与 rel 规范

游戏资源分布在两个根：`local` = `LocalData\<玩家>\0000`（按需下载），`stream` = `masterduel_Data\StreamingAssets\AssetBundle`（随安装包下发）。工具内部统一相对路径：`local/xx/hash` 或 `stream/xx/hash`；旧版清单里的裸 `xx/hash` 一律按 local 处理。

## 2. core.py — 共用底座

| 成员 | 逻辑 |
|---|---|
| `TOOL_DIR` | 打包成 exe 后 `__file__` 指向临时解压目录，改用 `sys.executable` 所在目录持久化配置/索引 |
| `detect_game_root()` | 注册表（HKCU/HKLM 的 Steam 键）→ 常见安装路径 → `libraryfolders.vdf` 解析其他 Steam 库 → 校验 `masterduel.exe` 存在 |
| `find_data_dir()` | `LocalData\*\0000` 中选文件数最多的（应对多账号） |
| `Paths` | 派生 data_dir / stream_dir / backup_dir / manifest_file；`root_of`、`bundle_path`、`backup_path` 处理 local/stream/旧版裸 rel 三种形式 |
| `Manifest` | 读写 manifest.json（`{"replaced": {rel: {time, source, added}}}`），`record()` / `remove()` / `entries()` |
| `backup_original()` | 只备份一次。返回 `backed_up`（新备份）/ `exists`（跳过）/ `added`（游戏里没有，新增）；兼容旧版裸路径备份 |
| `replace_file()` | 整包替换：备份 → `copy2` 覆盖（目标经 `bundle_path` 解析，保留 hex 子目录层级）→ 记清单 |
| `write_bundle_bytes()` | 单图/镜像替换：备份 → 重打包字节写回对应根 → 记清单 |
| `_effective_backup()` | 实际存在的备份路径（兼容旧版 local 裸备份） |
| `_remove_with_retry()` | 删除文件；WinError 32（杀软/索引短暂锁定）时退避重试至超时（默认 10s，0.2s 起步 ×1.5 递增）；仅占用类错误重试，其他异常直接抛出 |
| `restore_one()` / `restore_all()` | 有备份则还原并删备份；`added` 标记的删除文件。`restore_all` **两阶段**：先全部拷回再统一删备份（写删分离降低占用竞争），删除成功才移除清单记录（失败的保留，Tab3 可见，再还原即重试）；返回 (还原数, 删除新增数, 失败列表) |
| `is_game_running()` | `tasklist /FI "IMAGENAME eq masterduel.exe"` |

### scan_pack_source — Mod 源目录扫描

递归扫描，只识别游戏 Bundle 文件（文件名 8 位 hex；父目录为 2 位 hex 时直接作为目标子目录，父目录不是时按文件名前两位推导——兼容素材包平铺布局如 `NSFW\12b8f44c`），其余（预览图、作者备份等）一律忽略并计数。

**按 rel 聚合多变体**：不同文件夹里的同名 Bundle（`xx/hash` 相同）聚合成同一 rel 的 `variants` 列表，由界面层让用户逐个选择。返回：

```python
{"items": [{"rel": "5d/5df9f7a4",
            "variants": [{"path": Path, "size": int, "label": "ver1"}, ...]}],
 "skipped": 忽略文件数}
```

**变体 label 取名规则：**

1. 路径中含 `0000` → 取最后一个 `0000` 的父目录名（如 `ver1`）
2. 无 `0000` 层 → 取 hex 目录之上的相对路径（如 `ver1`），根目录平铺则为 `""`
3. 同一 rel 内 label 撞名 → 回退为更完整的来源路径；仍撞名 → 追加 `#1`、`#2` 保证唯一

## 3. cards.py — 卡图索引与替换

### 索引数据库（`card_index.sqlite`）

- 表结构：`cards(card_id, root, rel_path, path_id, width, height, format, mip, kind, over)`，主键 `(card_id, root, rel_path, path_id)`——同卡号同路径的 RGBA32/DXT5 两个贴图可同时入库不冲突
- `over`：是否超框美术（1 = 是）。判定规则：container 路径以 `.png` 结尾且贴图高 1024——普通卡图是 `.bmp`（512×512 或 512×1024 竖版），超框美术固定是 512×1024 的 `.png` 完整卡面
- `init_db()` 检测旧版 v1 结构（缺 root/path_id 列）自动 drop 重建；仅缺 `over` 列时 `ALTER TABLE` 补列（默认 0，重建索引后才有准确值）
- 另有 `meta(k, v)` 表存元信息（如 total_files）

### scan_index — 索引重建

- 遍历 local + stream 两个根的全部文件，8 线程并发（`ThreadPoolExecutor`）解析
- `_inspect_bundle()`：读 Bundle 的 container 清单，只收路径含 `card/images/illust/`、属于 common/tcg/ocg、尺寸 512×512 或 512×1024 的 Texture2D → 排除图标、3D 材质、卡框等同名数字贴图
- 卡号取贴图名（纯数字），否则取文件名；非数字跳过
- 每 500 条批量 `INSERT OR REPLACE`，进度经回调上报

### 查询

- `index_ready()`：索引库是否已有数据（整包替换前据此提示"建议先建立索引"）
- `get_card_rows(conn, card_id)`：一张卡的全部资源，按 local 优先 → common→tcg→ocg 排序，第一条即首选预览；每行带 `over` 标记
- `official_card_ids()`：CARD_Prop 顺序 ∩ 索引中实际有图的卡（浏览列表顺序来源）
- `browse_card_ids()`：`official_card_ids()` + 索引里 `over=1` 但不在 CARD_Prop 的超框专用 ID（如 22804、22768、3105），保证超框美术可在列表中浏览
- `load_overframe_map(paths)`：读 `0000\99\99f84cce` 里的 TextAsset `of_card_asset`，返回 `{超框美术ID: 原图ID}`（23 条 little-endian `<HH>`）；用于给无卡名的超框 ID 回退显示原卡名
- `get_modded_card_ids()`：manifest 的 rel 经索引反查卡号集合（400 条一组分批 IN 查询；结果按 manifest 键缓存，替换/还原后调 `invalidate_replaced_cache()` 失效）

### 卡名库加载

- `load_game_names()`：优先 `game_card_names.json`（官方，含 `__ids__` 有序表）→ 回退 `card_names_full.json`（旧第三方完整库，兼容 `jp` 键名）
- `load_card_names()`：最旧的 `cards.json` 简表，兜底

### 卡图读写

- `_find_texture(env, path_id)`：按 path_id 精确定位贴图；对不上时兜底取 Bundle 内第一张纯数字名贴图
- `_write_texture_rgba32(tex, img)`：PIL 图转 RGBA → resize 到原尺寸 → 垂直翻转（对齐 Unity 纹理坐标）→ 写 RGBA32（`m_TextureFormat=4`）→ MipCount=1、关 MipMap → 清 StreamData → `tex.save()`
- `read_card_art()` / `export_card_art()`：预览与 PNG 导出；超框美术（`over=1`）传 `overframe=True`——① alpha 是游戏端合成用的遮罩（框外溢出部分与效果框延续），照着 alpha 显示会让整张卡发白；② 贴图是 704×1024 版式横向压缩成 512×1024 存放，须拉伸回 704×1024（`OVERFRAME_W/H`），否则显得压扁
- `replace_card_art()`：用本地图片（文件路径或 PIL Image——后者来自裁剪窗口）替换该卡索引内的**全部** Bundle（跨根、跨版本），默认经 `same_art_card_ids()` 把同名同图的其它卡号（区域双建档）一起写入，`extra_ids` 可由界面传入避免重复计算；异画原图像素不同不会命中；返回写入数
- `same_art_card_ids()`：按 `(简中, 英, 日)` 卡名全等找候选，再用 `_row_fingerprint()`（解码 RGBA 后 MD5，优先读备份）比对首选卡图，命中即同一张图；候选超过 20 或名字为"未知"时放弃

### sync_mirror_bundles — 整包替换后的镜像同步

1. 用 UnityPy 读取每个 Mod 文件，按贴图名提取 `{card_id: PIL 图}`
2. 同名同图卡号联动：`same_art_card_ids()` 以备份中的原图指纹比对，把图片补到孪生卡号；异画不命中
3. 经索引反查这些卡号对应的全部其他 Bundle（排除刚被覆盖的）
4. 逐个重打包写入（`_write_texture_rgba32` + `write_bundle_bytes`，先备份）

## 4. gamedata.py — 官方卡名提取

```
masterduel_Data\data.unity3d
  └─ UnityPy 遍历 TextAsset
       ├─ CARD_Prop  ─┐
       ├─ CARD_Indx  ─┼─ XOR 解密（密钥暴力搜索）→ zlib 解压
       └─ CARD_Name  ─┘
            │
            ├─ Prop：偏移 8 起每 8 字节一条，低 2 字节 LE uint16 = 内部卡号（实装序列）
            ├─ Indx：每 8 字节一条，低 4 字节 LE uint32 = 卡名偏移（丢弃首条）
            └─ Name：按偏移切分 UTF-8 文本
```

- 解密算法来自社区（akintos / RndUser0）：`_xor()` 每字节密钥与偏移、key 相关；`_find_key()` 用 zlib 头首字节 `0x78` 快速过滤候选 key，再完整解压验证
- 语言判定：第 3001 号占位卡的译名锚点（`Unknown`/`アンノウン` 等）；中文锚点「未知」时再用 4007 号是否为「青眼白龙」区分简中（zh-CN）/繁中（zh-TW）
- 三表顺序一致：第 i 个卡号 ↔ 第 i 个卡名；逐语言容错（单个语言解压失败跳过）
- `save_game_names()` 输出 `game_card_names.json`：`{"__ids__": [有序卡号], 卡号: {"cn","en","ja"}}`，`__ids__` 按 CARD_Prop 顺序（约等于游戏收录顺序）

## 5. app.py — 界面层

### App（主窗口）

- 启动：读 `config.json` → 无配置则 `detect_game_root()` → 检测失败弹窗引导手动选择；`Paths` 派生全部路径
- 顶栏：游戏目录显示/选择/自动检测 + 游戏运行状态提示；底栏：状态栏（备份数 / Mod 状态文件数）
- **线程模型**：`run_bg(fn, on_done)` 后台线程执行，结果/异常塞进 `ui_queue`；主线程 `_poll_queue` 每 100ms 消费队列——`done` 消息执行完成回调、`prog` 消息执行进度回调（早期版本 prog 被静默丢弃导致进度条不动，已修复）；单个回调异常被捕获，不阻断轮询——所有耗时操作（索引、替换、还原、镜像同步）均走此模式，界面不卡死
- **操作互斥**：`App.index_running` / `App.pack_running` 标志。「建索引」与「整包替换」任一方开始时置位并禁用对方按钮，完成回调（成功/失败均执行）复位并恢复——防止两边并发争抢同一索引数据库（sqlite 锁冲突）

### PackTab（Mod 整包替换）

- `scan()`：调 `core.scan_pack_source` → 存在多变体 rel 时弹 `_pick_variants` 逐选窗口（每行单选按钮 + 顶部一键全选 + 可滚动列表）→ 生成 `self.items`（含 rel/path/size/variant/added）→ 树形预览（相对路径/大小/来源版本/类型）
- `execute()`：互斥检查（`index_running` 时拒绝）→ `cards.index_ready()` 为假时弹"建议先建立索引"（可继续）→ 确认 + 游戏关闭检查 → 置 `pack_running` 并禁用对方按钮 → 后台逐文件 `core.replace_file` → `cards.sync_mirror_bundles` 同步镜像 → done 无条件复原 UI（清标志、恢复双方按钮、清空进度文本——早期版本漏恢复导致替换后界面"假卡死"，已修复）→ 刷新状态与还原页
- 列表双击/右键 → `BundlePreviewDialog` 预览该 Mod 文件的 Bundle 内容

### CardTab（卡图浏览换图）

- `build_index()`：互斥检查（`pack_running` 时拒绝）→ 置 `index_running` 并禁用对方按钮 → 后台执行 `cards.scan_index` + `gamedata.save_game_names` → done 清标志并恢复（`exec_btn` 依扫描列表是否为空条件恢复）
- 搜索：内存索引 `[(card_id, 首选行, blob, is_over)]`，blob = 卡号 + 中/英/日卡名小写拼接（超框行另加「超框」及 `load_overframe_map()` 指回的原卡三语卡名），子串匹配；「仅显示已替换」经 `get_modded_card_ids` 反查；「类型」下拉（全部/仅超框/仅普通）按 `is_over` 过滤，命中超框的行卡名后缀「（超框）」，无卡名的超框 ID 回退为原卡名或「超框卡图 &lt;ID&gt;」
- 卡名取值 `_get_name()`：当前语言 → （超框 ID 先借登记表原卡名）→ 其它语言 → 旧卡名库；`"No.<卡号>"` 是游戏数据里的占位中文名，`_is_placeholder()` 视同无卡名，避免列表显示「No.22768」
- 分页：每页 300 条，翻页/跳页
- `on_select()` / `_show_card()`：先 `_sorted_rows()` 按 root/kind + **Bundle 文件 mtime 新→旧**排序（避免同类型多版本依赖索引写入顺序）→ `_pick_rows()` 选版本行（「自动」时日语取 `ocg`、其余语言取 `tcg`；「TCG」「OCG」固定；「并排对比」返回 tcg+ocg 两行）→ `_show_images()` 单图 280px / 双图 132px，标注 TCG（和谐版）/OCG（原版）及 `_bundle_tag()` 的新版/旧版 → 刷新卡名与资源信息（多资源时附日期）；切换语言或版本模式后同样重绘当前卡
- `replace_art()`：选图后弹 `CropDialog` 裁剪（可跳过）→ `same_art_card_ids()` 找同名同图卡号，确认框列出并计入资源数 → 后台调 `cards.replace_card_art(... , extra_ids=twins)`（**sqlite 连接在线程内自建并关闭**，避免跨线程使用主线程连接）替换这些卡号的全部资源（tcg/ocg 双版本一并写入）→ 刷新预览与已改标记。超框美术（`over=1`）裁剪比例取 `cards.OVERFRAME_W/H`（704×1024）而非贴图实际尺寸，`_write_texture_rgba32` 再按贴图原有尺寸写入（官方超框 512×1024；本工具制作的超框 704×1024）

### RestoreTab（还原管理）

- 数据源为 manifest 清单；五种排序（路径/时间/方式/类型/有无备份），列标题点击可翻转升降序
- 列表双击/右键 → `BundlePreviewDialog`（覆盖类文件双源：游戏当前（mod) / 原版备份，顶部下拉切换对比）
- `restore_selected()` / `restore_all()`：游戏关闭检查后调 `core.restore_one` / `core.restore_all`；单文件恢复前先经 `_linked_rels()` + `cards.rel_card_map()` 反查卡号，把选中文件扩展到同一卡号在清单中的全部 Bundle（tcg/ocg、同路径重复版本），并追加 `same_art_card_ids()` 找到的同名同图卡号（异画不命中），确认框提示联动数量；逐文件容错，结果弹窗汇总成功数与失败明细

### BundlePreviewDialog（Bundle 资源预览）

- 左侧 Bundle 内对象列表（名称/类型/尺寸，Texture2D/Mesh/Material/AudioClip 等），右侧贴图预览（自动缩放，显示名称/尺寸/压缩格式），支持选中贴图导出 PNG；非贴图类型列出但不可预览
- **加载经 `UnityPy.load(io.BytesIO(文件字节))`**：读入内存即释放文件句柄——否则预览窗口存续期间持有句柄，还原/替换删除该文件时撞 WinError 32（自己锁自己）
- 支持 `sources=[(显示名, 路径)]` 多源切换（Tab3 对比 mod 版与原版备份）

### CropDialog（单图替换裁剪）

- 选图后自动弹出，按目标卡图尺寸锁定比例（512×512 → 1:1，512×1024 → 1:2）；拖动移动选区、四角缩放、区外点击重选，底部实时显示「选区尺寸 → 输出尺寸」
- 三个出口：裁剪并替换 / 不裁剪用原图（拉伸，比例不符会变形）/ 取消
- 裁剪结果以 PIL Image 直接传给 `cards.replace_card_art`

### 通用右键菜单

- `_attach_entry_menu(entry, readonly)`：输入框（源目录/搜索/页码/卡号）右键 剪切/复制/粘贴/全选（走 `<<Cut>>/<<Copy>>/<<Paste>>` 虚拟事件）；readonly 时仅复制/全选
- `_attach_tree_preview_menu(tree, cmd)`：树列表右键「预览 Bundle 内容」——先 `identify_row` 选中右键所指行再弹菜单，与双击等效
